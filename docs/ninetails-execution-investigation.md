# 九尾妖狐处决修复调查

日期：2026-10-11。本文记录飞缘魔替换角色在九尾妖狐倒地后，重攻击仍触发旋转攻击的问题，以及原生处决链的资源要求和现场验证结果。

## 问题与原生入口

Beta 5.4.1 的八岐大蛇修复限定了蛇头身份、倒地动作及大蛇任务状态，因此不会为九尾妖狐绑定处决资源。九尾妖狐使用独立的原生分支，不能仅扩大大蛇的目标范围。

原生已加载武器动作包中的入口为：

| 阶段 | 原生动作或查询 | 作用 |
| --- | --- | --- |
| 重攻击入口 | 3008 | 由原生重攻击输入进入武器处决分支 |
| 九尾分支 | query474 + query381 → 4026 | query474 检查九尾模板，query381 检查目标原生可处决标志；原生过渡为 3 帧 |
| 起手 | 4026 / motion1210 | 登记待配对目标，保留原生事件与位置处理 |
| 配对成立 | query208 → 1273 | 使用原生配对状态进入第二段 |
| 玩家处决 | 1273 / motion1211 | 原生配对动作，后续退出到武器待机 3000 |
| 目标处决 | 1274 / motion31010 | 原生目标动作，包含死亡事件，后续退出到 3177 |

query380/query381 的后续分支仍用于八岐大蛇 3491。九尾分支在它之前，正式修复需保留原生分支顺序和资源归属。

## 配对与动作选择

控制器的锁定引用 `+640`、待配对引用 `+5D8`、活动配对引用 `+5B0` 作用不同。4026 的 local79 事件使用 descriptor `+30=13`、`+31=7`、`+32=100`，从锁定引用取得目标并登记待配对引用及定位参数。

1273 的 local118 和目标 1274 的 local78 使用 `+30=15`、`+31=12`，处理处决位置与变换。两者的 descriptor `+2E` 均为无效值，不能把相邻字段误解为移动缩放。

目标 1274 的选择由原生控制器更新完成，代码 RVA `0x7172BD` 读取配对另一方的当前动作编号，`0x7172C1` 加 1，随后调用原生动作应用入口 `0x70ECE0`。因此玩家动作 1273 对应目标动作 1274。该路径要求有效的双方配对引用、发起方动作的配对标志，以及原生接收方同步状态。

## 主辅动画与事件资源

玩家处决需要当前已加载武器包的两层动画及两层事件资源。只绑定主动画会遗漏原生事件或第二层的查询路径。

| 动画 | 已核对帧数 | 主事件条数 | 辅事件条数 |
| --- | ---: | ---: | ---: |
| 1210 | 114 | 38 | 38 |
| 1211 | 569 | 56 | 48 |

1210 的事件调度包含超过动画帧数的合法时间值，不能用“所有事件时间不得超过动画长度”作为资源有效性条件。资源验证仍需检查映射唯一性、描述表边界、条数、所属原生资源及主辅层对应关系。

从现场 VM_READ 复制的资源和完整原生查询代码，在离线 CPU 仿真中确认：4026 起手期间，原生 query86 返回真，可使共享武器分支提前离开处决。保护因此限定在已验证的九尾起手记录和资源绑定内，并验证角色、目标、当前代次及待配对状态。它不修改精华、九尾 HP、死亡标志或任务状态，也没有在游戏进程中远程调用该查询。

## 死亡与剧情事件

目标 1274 第 500 帧的 local74 仅清理控制器字段。真正的死亡入口是第 **510 帧 local77** 的 descriptor `+3E=0`。

原生事件处理经 `0x70A314 → 0x731150 → 0x730970` 调用原生伤害路径。该路径将伤害提升至当前 HP，并经 `0x7AFAC0` 更新死亡状态。代码还包含 `0x730D45 → 0x76B890 → 0x886D00` 的 `character_dead` 任务回调入口，但它要求角色通知标志和脚本控制器满足条件。九尾模板另有 `0x9084C0` 的处决记录路径。

成功场景的角色通知标志未置位，因此本次采样不能证明执行了 `character_dead` 回调，也尚未直接确定剧情推进使用哪一条任务通知路径。现场验证已确认原生死亡和剧情推进；正式修复保留这些原生事件及判断。

因此，看到处决动画或目标倒下都不足以证明修复完成。验证必须同时确认目标原生死亡状态、剧情推进和正常控制恢复。

## 现场结果与发布边界

候选修复使用原生重攻击输入、当前武器包资源和原生配对/死亡事件完成处决。采样观察到目标动作经过第 511 帧、玩家动作经过第 512 帧，目标 HP 为 0、原生死亡状态为 1；随后临时处决阶段清零，玩家返回动作 0，锁定引用清空。用户确认剧情继续并恢复控制。

上述结果证明当前场景候选的处决链有效。正式动态版本的 24 项 CPU 测试已验证资源发现、主辅层映射、代次与重新加载失效保护、原生退出及 ABI。12 组加载布局中，73 个未改动补丁的代码和入口共完成 876 次逐项一致性比较；8 个原有大蛇处理体完整保留，并验证全部 8 只蛇头的动态路由。

独立复核还发现并修正了事件偏移表的 32 位边界加法溢出，以及同代次遗留九尾阶段可能遮蔽大蛇处理的问题，两者都有拒绝或回退测试。正式工具完整退出游戏后重新启用的实机结果单独记录如下。CPU 仿真可以验证保护边界和 ABI，但不能代替游戏内剧情验证。

另一次动态绑定仿真复制了现场 145 页已加载资源，未发生页面读取失败。无重攻击输入和有重攻击输入两个分支均完成资源发现，保留 ABI，写入限于离线堆栈与私人绑定。因为原场景目标已死亡，该测试仅在复制的内存中还原了已记录的倒地状态；游戏内没有改写目标或重新触发处决。此结果验证资源查找，不能代替正式 EXE 的新进程实测。

## 正式版与后续复用

Beta 5.4.2 仍使用 81 处原生入口。八处共享载荷先判断当前九尾资源归属，再转入九尾处理；原有大蛇处理体原样保留，其余 73 处逐字节一致。九尾绑定位于独立的 512 字节私人区域，避免复用大蛇的目标、阶段或资源指针。第一次查找按当前角色和已加载武器包发现资源；角色代次变化时清空旧绑定并回退，下次查找重新发现。

正式 Release EXE 随后通过完整重启游戏、主菜单启用和九尾最终处决复测。用户在最终采样开始前已按重攻击，确认正常处决及剧情继续，随后另行确认移动和菜单已恢复。只读核对显示全部 81 处正式补丁一致，无临时补丁或诊断钩子；九尾 HP 0、原生死亡状态 1、目标动作 17，玩家动作 0、控制 mode704 为 0、双方配对与锁定清除，九尾私人阶段 0、接受次数 1。

这次正式版的观察范围为处决后的结束状态，没有记录其逐帧动作过程，也不把场景候选第 510/511 帧的证据归属于正式 EXE。精确 EXE、新进程实测结果和观察哈希保存在 [Beta 5.4.2 验证记录](validation-beta5.4.2.json)。Beta 5.4.1 的大蛇实机记录仍属原版本，Beta 5.4.2 的代码保留和 CPU 路由证据没有被描述为新的完整大蛇战斗。

其他 Boss 若有类似处决，需要先独立确认目标身份、原生可处决查询、起手到配对的动作链、主辅资源、真正的死亡事件和结束控制路径。验证时分别检查动画、原生死亡、剧情推进与控制恢复，不能以目标倒地或动画播完作为完成判据。本次九尾无需增加大蛇的几何查询保护，没有将其无条件扩大到其他 Boss。

本文仅保留动作编号、资源结构、代码 RVA 和验证结论，不包含游戏堆地址、进程编号、原始游戏资源字节或用户存档。
