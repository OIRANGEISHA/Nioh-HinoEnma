## Beta 5.4 完整重启后的失效与修订

用户完整退出并重启进程，在主菜单用 Beta 5.4 启用飞缘魔，最后蛇头倒地且锁定后，T 仍触发旋转攻击。只读确认全部 80 处补丁与载荷正确，原生目标为就绪动作 3205、处决查询 381 为真、生命 1、七头死亡且任务临时记录已初始化；不是遗漏启用或目标未就绪。

私有绑定停在 common bank 发现之后，尚未保存重攻击过渡，MAGIC、phase、accepted 都为 0。当前飞缘魔 idle0 与 common bank idle0 是不同地址、不同所有者，后者启用且属于已核对的 common bank。Beta 5.4 的 `cmp native_common_idle, current_hino_idle` 错误拒绝了这个正常布局；合成 fixture 把两个 idle0 合并成一个，未覆盖此差异。

此前成功的现场绑定从 common idle0 读取原生重攻击过渡，同时另存飞缘魔当前 idle0 用于入口和结束恢复，从未要求两者地址相等。离线捕获资源重放可复现正式入口在该地址比较处分支回退。不能只删除比较：后面的 kind0 过渡查找也必须改为从 common idle0 读取。

Beta 5.4.1 的私有 `0x58` 保留飞缘魔 idle0，新增 `0x1F0` 保存经过启用、唯一性和银行所有权核对的 common idle0，kind0 原生重攻击过渡从后者发现。此槽在 512 字节绑定区内，与查询保护字段无重叠。双方原生动作记录、过渡、生命、任务和存档均不直接写入。

默认 CPU fixture 改为两个分离的待机所有者，并给飞缘魔待机提供旋转攻击过渡。新增回归覆盖正确取 common 重攻击、双方原记录保持不变，以及缺失、禁用、重复、错误所有者、缺少重攻击或无效过渡数组时安全回退。处决测试从 23 项增至 25 项；源码总数从 166 项增至 168 项。离线通过与新 EXE 的完整游戏实测必须分别记录。

### 重启后的处决起手被九十九条件打断

修正待机资源绑定后，现场记录确认游戏已接受 `3008 → 3491`，但接着请求 `169 → 0`，未进入 4000。当前九十九槽为满值；原生 query86 在 3491 的配对事件登记之前返回 true。3491 参数不含原生用来抑制此判断的 bit29，活动配对字段 `5B0` 也尚为空。169 是九十九启动分派，飞缘魔动作银行中缺少它，因而回退到 idle。

临时 query86 保护仅覆盖经过全部实例、资源归属和最后蛇头条件核对的阶段 1、当前 3491、活动配对为空、锁定目标仍为绑定目标的区间。待配对字段 `5D8` 可以尚为空或已经指向该目标；外来非空引用必须拒绝。保护保留原生 false 初始化，经 `73AAB1` 退出，原路径重放原来的两条 MOV。完整原生查询帧为 `[736CB0, 73AB00)`。

14 项隔离 CPU 范围与 ABI 试验通过；复制当前真实资源后的完整原生 query86 重放也通过，分别验证原路径返回 true、待配对为空和已登记目标的保护路径返回 false。现场保护命中 3 次，169 请求消失，动作链进入 4000、目标进入 4001，随后经 3000 回到飞缘魔 idle。

该轮仍未完成任务：用户看到完整击杀动作和蛇头倒下，但剧情未继续；只读结果为目标生命仍 1、原生死亡计数仍 7、处决阶段 0、待机恢复计数 1。当前主辅 1200/1201 的 TMG 描述符、19/42 项排程，以及玩家 4000 的 160 字节动作参数，与历史成功记录逐字节相同。尚在检查目标自身 4001 的死亡事件；本轮目标为 `8F795/3205`，历史成功目标为 `1DC1C/3203`。不能把动画完整播放或配对解除视为原生死亡已触发。

## 原生动作、资源与事件链

本场景的链条是 `3008 → 3491（motion 1200）→ 4000（motion 1201）→ 3000 → 飞缘魔 idle 0`。

- 3008 是原生重攻击入口。只有游戏原本的重攻击输入被接受、当前角色与目标符合条件时，才临时返回对应的武器动作过渡；其余输入保留原路径。
- 3491 使用 motion 1200，过渡为 3 帧，资源长度为 95 帧、60 FPS。查询 208 进入 4000 的第二段配对动作。
- 4000 使用 motion 1201，长度为 409 帧、60 FPS。目标侧原生配对动作为 4001。
- 主、辅运动资源及主、辅 TMG 事件视图都必须提供。事件描述的 schedule 数分别为 19、42；查找必须匹配各自的事件所有者，不能把主层事件表给辅层使用。
- 第二段第 251 帧的原生全局事件 10019 解除配对。原生函数 `72F090` 清理双方配对引用，未直接写生命或调用死亡回调；此前将其称为击杀事件仅依据同一帧附近的现场相关性，现予以更正。真正的目标死亡事件与条件需单独验证，原生逻辑负责生命、死亡计数、剧情与任务推进。
- 原生终止动作 3000 归回飞缘魔 idle 0，并清空私有处决阶段。必须确认过场后可控制，不能只检查目标生命为 0。

正式绑定按当前玩家、控制器、目标实例头、加载的武器包、动作银行、运动映射和事件管理器逐项确认。Beta 5.4.1 匹配上表八对身份、就绪动作 3203/3204/3205、原生处决标记、目标生命 1，以及已初始化的七头死亡状态。所有树、数组和映射循环有上限；缺项、重复项、错误索引、错误帧长或描述越界均回退原路径。

资源来自已加载的原生所有者，不缓存本次现场的堆地址。角色生成周期或实例头变化后重新绑定；已进入配对阶段时不接受第二次重攻击，也不重新绑定另一只蛇头。失败绑定只影响私有数据，不替换原生对象字段。

## 两次卡顿的数值原因

原生查询调用点 `6E86B8` 所对应的起点与终点重合。函数 `7DCF10` 计算方向长度并归一化时，零向量除以零得到 NaN；无效方向进入几何遍历后，原生循环未能结束。

入口保护只作用于正在执行本次处决的当前飞缘魔和当前配对蛇头，以及核对过的原生调用上下文。零长度或包含 NaN/Infinity 的查询返回原生无命中值 `FFFFFFFF`；有限非零查询仍完整走原函数。

对已陷入循环的查询，还需验证保存的玩家引用、原生嵌套返回地址 `7DED33`、无命中标志和无效端点，才能退出到 `216ADD`。这是该晚期栈帧的无命中尾声，负责恢复 R12–R15 与 XMM7–XMM9。`216B54` 是另一条早期尾声，不能替代；否则会跳过应有恢复并破坏调用者状态。错误尾声在离线验证阶段被排除，未接入游戏。

第一次保护要求双方配对引用互指，能恢复第 11 帧。原生击杀后双方 `5B0` 引用会清空，所以第 266 帧不再满足此条件。第二版允许这个特定的击杀后区间，但仍要求当前实例头、控制器及其 4000/4001 动作有效，双方配对引用均为空、目标原生生命为 0、原生八头死亡计数为 8 且初始化标志有效。其他场景、外来引用、已有命中和正常查询保持原路径。

正式包动态确认 4001 动作属于目标当前动作银行，不依赖现场记录地址；已陷入查询的保护也以原生返回地址、保存的所有者及无效数值确认作用范围，排除了固定栈或几何对象地址。
