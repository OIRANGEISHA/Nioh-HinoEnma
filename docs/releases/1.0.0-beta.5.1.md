# 1.0.0 Beta 5.1

适配 Steam《仁王 完全版》1.24.08。预发布测试版，2026-10-09。

## 本次更新

- 数字 **1** 新增战后浓姬／雪女的完整抓住吸血动画：适用于已经击败、仍在场景且所需受抓资源仍载入的目标。
- 配对结束后恢复原有倒地姿态，保持已击败状态。生命为 0 的战后目标不追加伤害或回血，不复活，也不直接写入任务或存档状态。
- 按当前玩家和目标实例检查所有权、距离、战后状态及资源，角色重新生成时使用当前绑定。
- 保留 Beta 5 的道具与盐修复、第一栏 2 号快捷道具及此前交互、守护灵、成长装备兼容。

Beta 5.1 adds a complete visual life-drain grab for the reported defeated Nouhime / Yuki-Onna with loaded reaction resources, using the existing digit 1 binding. The target returns to her defeated pose; no extra damage, healing, revival or direct mission/save-state write is added.

## 下载与使用

Release 仅上传两个附件：

- `Nioh-HinoEnma-1.0.0-beta.5.1-windows-x64.exe`：直接运行的 Windows x64 工具，不需要 CE 或 Python。
- `Nioh-HinoEnma-1.0.0-beta.5.1-source.zip`：完整公开源码、CT 源码、构建方法、使用和键位说明及构建记录。

从 Steam 启动游戏，停在 **NEW GAME / CONTINUE 主菜单**，运行本版 EXE 后载入关卡。角色切换需要返回主菜单再载入；每次重启游戏后再运行工具。从旧版升级时先退出游戏。同一次游戏不要混用不同版本或 EXE／CT。

## 键位

以下沿用当前已测试的游戏键位，数字键指主键盘数字行；更改游戏设置后操作可能不同。

| 按键 | 操作 |
| --- | --- |
| W / A / S / D | 移动 |
| J | 踢腿 |
| I | 挥伞 |
| K | 撤步 / 闪避 |
| Shift | 恢复精力 |
| Q + 空格 | 起飞 |
| Alt | 飞扑 / 俯冲 |
| 1 | 吸血；也用于受支持的战后浓姬／雪女抓取动画 |
| 2（第一栏道具快捷位） | 使用兼容道具；当前唯一支持的道具快捷位 |
| 5 | 地面和空中吼叫 |
| F6 | 净化附近常世；松开再按可再次触发 |
| 9 | 地面空闲、守护灵槽满时启动九十九并召唤守护灵攻击 |
| 游戏交互键，随后 W / S | 进入梯子后向上 / 向下攀爬 |

九十九期间，等守护灵退场、人物恢复地面空闲，再松开并按 9 可重复召唤。**快捷道具放到第一栏的 2 号快捷位**；其他快捷位置会触发飞缘魔技能或动作。兼容道具也可从背包选择“使用”。道场空格残心、空格＋2／3 近战切换教学、空格＋1／4 远程切换教学和 T 九十九教学保持；教学兼容不代表完整原生换武器或射击支持。

## 验证与限制

- 临时修订版由用户连续完成两次战后浓姬抓取，完整动画、恢复倒地姿态、移动和菜单正常。此实测与正式 EXE／源码构建验证分别记录。
- 本版已完成的离线、构建及正式工具验证和实际检查数量见 [Beta 5.1 验证](https://github.com/OIRANGEISHA/Nioh-HinoEnma/blob/v1.0.0-beta.5.1/docs/validation-beta5.1.json)。公开便携检查使用合成记录及显式 Win64 替身，不执行原生伤害／事件引擎或背包提交；不分发私有游戏代码或原始内存记录。
- 战后抓取仅确认已反馈的浓姬／雪女场景，不能据此认定全部战后 Boss 或尸体都支持。完整任务切换、存取档及所有角色重载情况尚未全面验证。
- **部分非关键道具使用仍未修复**。盐的新增 Common 205／85 受击路径仍为 CPU 检查范围；全部道具、词条、NPC、守护灵、地图和交互变体尚未逐一验证。
- 保留动作可能固定大笑、吼叫不叠加额外元素、原生射击及实际切换 Boss 武器未接入等既有范围。CT 在 CE 内直接启用未实测，推荐 EXE；Windows Beta 未作 Authenticode 签名。

The two consecutive post-defeat grab gameplay confirmations used a temporary revision. Production verification is recorded separately. Existing limitations and historical evidence retain their scope; this is not complete coverage of defeated Bosses, items, interruptions or mission transitions.
